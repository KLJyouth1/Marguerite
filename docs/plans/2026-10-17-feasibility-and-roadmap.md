# 2026-10-17 · 模型 × 工作台 × 岛屿 的可行性路线（基于实测）

> 本文只写**能验证的事实**与**能执行的步骤**。物理做不到的，直接标注"不可行"，不包装。

## 0. 实测硬件（`Win32_Processor` / `nvidia-smi` / `torch`）

| 项 | 实测值 | 对方案的硬约束 |
|---|---|---|
| CPU | i5-12500H，12 核 / 16 线程，2.5 GHz | CPU 训练 1.5B 极慢，只能做应急 |
| 内存 | 31.7 GB | 可承载 4-bit 1.5B 推理 + 数据管线 |
| GPU | **RTX 3050 Ti Laptop，4 GB 显存**，compute 8.6 | **4-bit QLoRA ≤1.5B 可行；3B 极限；7B 不可行** |
| PyTorch | **2.11.0+cpu（`cuda False`）** | 训练**根本没用 GPU** —— 这是"训练慢"的真正根因 |
| 缺失依赖 | `bitsandbytes` / `trl` / `llama-cpp-python` | 4-bit QLoRA、SFT 训练器、GGUF 导出都缺 |
| 磁盘 | C 27 GB / D 108 GB / E 93 GB 可用 | 够放 1.5B 权重 + 适配器 + 数据集 |
| 系统 | Windows 11 专业版 | 无 WSL 需求；Blender bpy 走 Windows 原生 |

## 1. 需求 → 可行性矩阵

| 需求 | 本地可行性 | 正确路径 |
|---|---|---|
| 浏览器/办公/3D/DCC/代码 定向训练（1.5B 级） | ✅ | 4-bit QLoRA（需装 CUDA torch + bnb），单轮 1–3 小时 |
| 3B 级定向训练 | ⚠️ 极限 | 4-bit + grad checkpoint + 短序列，实验性 |
| 7B 及以上 | ❌ 显存不足 | 只能调用托管 API（工作台已支持配置 provider） |
| 万亿参数 / 全模态旗舰推理 | ❌ 本地训练物理不可行 | **接入**（API），工作台三档路由里作为"旗舰档" |
| 3D / 世界模型训练 | ❌ 4 GB 显存 | **集成**开源（TripoSR / TRELLIS / Hunyuan3D 等）或 API，本地只做**生成调度 + 资产热加载** |
| 类脑稀疏（MoE / 激活稀疏） | ⚠️ 只能小规模 | 不训大 MoE；改为**在 1.5B 上挂多个稀疏决策头**，推理时只激活相关头 |
| 知识蒸馏 | ⚠️ 教师需算力 | 用 API 教师生成软标签 + 本地学生 1.5B 蒸馏 |
| 长程任务 / 复杂项目 | ✅（工程问题，非训练问题） | worktree 并行 + subagent 编排（已落地） |

**结论**：工作台要"覆盖旗舰到极速的四档"，靠的不是把四档都**训**出来，而是
**本地小模型做路由与高频任务 + 托管大模型做重推理 + 工具/记忆/3D 管线补能力**。
这就是唯一在 4 GB 显存下成立、且诚实可交付的架构。

## 2. 五个务实创新（都能落地并验证）

1. **修环境即提速 10–50×**：装 CUDA 版 torch + bitsandbytes。当前 GPU 空转，先把它用起来，
   这是所有训练的前提，也是投入产出比最高的一步。
2. **稀疏决策头（brain-like sparse）**：不训练大 MoE。在 1.5B 主干上挂 `routing / tool_choice /
   intent / emotion / nli / abstain / grounded` 等**轻量头**，推理时按输入类型只激活 1–2 个，
   其余旁路。收益：延迟与成本骤降，且能按头独立增量训练（不必整体重训）。
   *现有基础*：`data/datasets` 里已有这 11 类数据与 `decision/engine.py`，改动是"接上稀疏激活"而非从零。
3. **记忆式持续学习（"人上网学、记下来"的工程等价物）**：权重级持续学习在 4 GB 上不现实，
   但可以做到**检索即学习**：结构化记忆库 + 向量检索 + 夜间把当天新增结论**蒸馏进适配器**。
   这样"学到新东西"不需要重训全模型，只需要小步蒸馏。
4. **并行多模型编排（回答"为什么不能并行"）**：能并行。工作台已有四档 tier（旗舰/高效/极速/全模态），
   下一步是把**路由决策交给本地 1.5B**（便宜、离线、快），按任务特征并发调用不同档位模型，
   再合并结果。这比"单模型全能"在成本与质量上都更优。
5. **3D/游戏闭环（回答"生成 3D 开放世界"）**：已落地的三段——GDD 契约 → 程序化地形/道具 →
   GLB 热加载；下一步接 **Blender headless 资产管线**（已写 `blender/asset_pipeline.py`）与
   开源图生 3D 服务的调度层。**训练不在本地做，生成与集成在本地做。**

## 3. 阶段计划（每阶段都有验收证据）

| 阶段 | 内容 | 验收证据 |

| **P1（1–2 天）** | 扩四类定向数据（浏览器 / 办公 / 3D-DCC / 代码），以 16c 为起点训 **V0.17** | 新 `train_stats.json`（样本数、loss）、评测台分数对比 16c |

## 4. 硬边界（不粉饰）

- **4 GB 显存**决定了本地训练上限在 1.5B（4-bit）。任何"本地训万亿/全模态/世界模型"的说法都是假的；
  正确做法是接入与调度。
- **"所有 2026-10-16 之前的架构都过时"**：这个判断在方向上成立（单一模型无法同时满足旗舰推理、
  全模态、3D 生成与 4 GB 运行），但**解决方案不是"训一个更大的"，而是"编排一个更好的"**。
- **时间**：每轮真实训练以小时计；数据扩充与评测是主要工作量，不是点一下就跑完。
- **网络**：本机 DNS 被投毒（已用 hosts 固定 GitHub），大文件下载需重试；`pypi` 下载 2.5 GB 需留意中断。
- **凭据**：此前 PAT 已明文暴露，必须先撤销重建。

## 四、剩余待修复项（3 项）

### QA-005（Warning）— UI 架构级，需跨文件重构

- **文件**：`webui/src/composables/useRequest.ts` + `useRpc.ts`
- **问题**：双轨 RPC 封装（useRequest 与 useRpcCall 都包装 rpc.call()）
- **影响**：架构冗余，开发者在 ChannelsView/OverviewView/CronView/AgentsView 等 10+ 文件中使用不同封装
- **建议**：将 `useRequest` 重构为 `useRpcCall` 的薄包装（保留 auto-toast + refresh 能力），或统一入口。需逐文件替换 import，工作量大。

### QA-006（Warning）— 组件重构

- **文件**：`webui/src/components/cron/CronDeleteDialog.vue` vs `ConfirmModal.vue`
- **问题**：CronDeleteDialog 独立实现确认弹窗，未复用 ConfirmModal
- **建议**：CronDeleteDialog 改为调用 ConfirmModal 并传入 title/message/callback，删除独立模板。

### QA-008（Warning）— z-index 体系级重分配

- **文件**：`AgentsView.vue:820/964`、`SkillsView.vue:633`、`CronView.vue:638/1963/2252`、`BaotaCredentialsDialog.vue:190`、`ProjectWorkspace*Dialog.vue`、`DiagnosticsBundleDialog.vue`
- **问题**：11 个不同组件共用 z-index:1100（视图级覆盖 + 对话框模态混用）
- **建议**：全局建立 z-index 层级规范：1000-1049 视图级抽屉/覆盖层，1100-1199 对话框/模态框，按域分配唯一值。

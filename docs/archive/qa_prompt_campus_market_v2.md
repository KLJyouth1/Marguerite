## 2. 核心方法论：双向观察闭环（必须执行）
每个功能点都走以下 6 步，缺一不可：
1. **截前台前置状态**：URL、页面文案、按钮、用户身份、截图。
2. **执行动作**：前台点击/提交，或后台点击/修改。
3. **抓 API**：记录触发的路由（如 `/index.php?...`）、HTTP 方法、参数、响应码、响应体。
4. **查数据库**：`SELECT` 对应表，确认写入/更新正确（状态、金额、时间、外键）。
5. **看后台对应页**：登录后台，确认管理页记录出现、状态一致、可干预。
6. **回前台刷新**：确认 UI 状态与后台/数据库一致，无延迟、无错乱。

**铁律**：未完成上述 6 步，不得标记该功能「已验证」；不得只截图不抓 API；不得只查页面不看 DB。

## 3. 禁止肢解为孤立小任务
以下行为属于错误执行，必须避免：
- ❌ 先测「登出跳转」、再测「登录页显示」等边缘点，跳过主链路。
- ❌ 把「注册」「登录」「学生认证」「开店」「充值」「支付」拆成互不相关的独立任务。
- ❌ 只验证前台页面是否存在，不验证后台对应管理页和数据库。
- ❌ 只做安全扫描，不结合业务流程验证漏洞是否真实可复现。

正确组织方式：**按「用户角色 + 完整流程」切块**，例如「买家 A 从注册到首次支付」是一条完整用例，必须贯穿前后台。

## 5. 执行顺序：先 P0 主链路，再 P1/P2
必须严格按以下顺序执行，P0 未完成不得进入 P1，P0 失败立即暂停上报。

### P0 核心交易链路（用户旅程）
按角色完整跑通：
1. **注册 → 登录 → 退出 → 再登录**（买家 A）
2. **学生身份认证**：提交资料 → 后台审核通过 → 前台状态变为「已认证」、权限开通
3. **充值**：买家 A 充值 → 余额变化 → 后台资金流水记录
4. **卖家开店**：卖家 A（个人）/ 卖家 B（商家）提交开店 → 后台店铺审核通过 → 前台店铺页可见
5. **商品发布**：卖家发布普通商品、租赁商品、竞拍商品
6. **咨询/议价**：买家咨询 → 卖家回复 → 议价 → 改价同步
7. **下单 → 支付 → 订单状态机**：下单 → 余额支付 → 订单完成/待发货 → 后台订单可干预
8. **租赁/竞拍成交 → 支付 → 订单**

### P1 店铺与信誉
- 店铺管理工作台数据看板
- 商品/订单/售后管理
- 信誉体系：评价 → 信誉分变化 → 前台展示

### P2 后台管控与风控
- 用户/认证审核
- 商品管控（下架/禁售/敏感词）
- 订单干预（改价/退款/发货）
- 店铺/内容管控
- 风控规则配置

## 6. 风控系统专项（必须给出「缺失补齐建议」）
后台管控与风控不是「看看有没有页面」，而是逐项检查是否**真正生效**。以下能力若无实现，必须标为缺失并给出建议：
- [ ] **登录安全**：异地/异常登录检测、登录失败锁定、登录日志审计
- [ ] **交易风控**：频繁下单/刷单识别、大额交易预警、退款欺诈识别
- [ ] **内容风控**：商品标题/聊天敏感词过滤、图片 OCR 违规识别、举报与下架
- [ ] **资金风控**：充值/提现限额、异常资金流水告警、对账机制
- [ ] **学生认证风控**：学号/身份证/学信网核验，防止伪造认证
- [ ] **店铺/卖家风控**：资质审核、违规店铺降权/封禁、保证金机制
- [ ] **竞拍/租赁风控**：恶意抬价、虚假租赁、超时未支付自动关闭

## 7. 安全漏洞检查清单（必须在业务流程中复现，禁止只扫描）
每类漏洞都要构造真实请求，确认能否利用，并给出利用链与修复位置。
- [ ] **SQL 注入**：登录、搜索、订单号、商品详情 URL 参数处尝试时间盲注/报错注入
- [ ] **XSS**：商品标题、咨询留言、昵称、评价处尝试 `<script>alert(1)</script>` 及 DOM 型 payload
- [ ] **越权**：买家 A 访问买家 B 的订单/地址；普通卖家访问 admin 后台接口；未认证用户访问认证后接口
- [ ] **CSRF**：修改密码、下单、退款等关键操作是否校验 CSRF token / SameSite
- [ ] **支付安全**：余额充值/支付是否可篡改金额、重复提交、绕过；回调是否校验签名
- [ ] **文件上传**：头像/证书上传是否校验类型/后缀/内容，能否上传 webshell
- [ ] **敏感信息泄露**：API 是否返回密码、token、数据库字段；错误信息是否暴露 SQL
- [ ] **认证绕过**：后台登录是否可暴力破解、session 是否可预测

## 8. 持续浏览器会话纪律
- 使用同一个浏览器实例打开前后台，通过 cookie/session 保持登录态。
- 切换前后台时不得清缓存、不得开隐私窗口、不得重新输入账号密码（除非测登录本身）。
- 每次「后台改动 → 回前台观察」必须在 2 分钟内完成，避免 session 过期导致误判。

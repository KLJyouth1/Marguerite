## 三、v3.0 新增修复项（3 项）

### QA-005（Warning）— RPC 双轨合并

- **文件**：`webui/src/composables/useRpc.ts`、`webui/src/composables/useRequest.ts`
- **问题**：双轨 RPC 封装（useRequest 与 useRpcCall 都包装 rpc.call()），10+ 文件使用不同封装
- **修复方案**：
  1. 扩展 `useRpcCall`：新增 `immediate`（控制自动挂载执行）、`toastOnError`（错误自动 toast）、`errorLabel`（toast 标签）三个选项
  2. 为 `useRpcCall` 新增 `refresh()` 方法（静默重取，不闪烁 loading）和 `perform()` 的 `silent` 参数
  3. 重写 `useRequest` 为 `useRpcCall` 的薄包装：默认 `toastOnError: true`，保留函数参数兼容，委托全部连接/准入/合并/重试逻辑
  4. `useRpcCall.execute()` 从 throw 改为返回 `null`（错误不冒泡），与 `useRequest` 语义一致
- **影响范围**：4 个直接调用方（OverviewView、ChannelsView、useCronJobs、useAgentsData）+ 6 个 `useRpcCall` 直接调用方，全部无行为回归
- **验证**：vue-tsc 通过 · useRpc.test 1/1 · OverviewView/ChannelsView 87/87 · SidebarSetupBanner/EmptyStateChips 7/7

### QA-006（Warning）— CronDeleteDialog 复用 ConfirmModal

- **文件**：`webui/src/views/CronView.vue`、`webui/src/components/cron/CronDeleteDialog.vue`（已删除）
- **问题**：CronDeleteDialog 独立实现确认弹窗，未复用全局 ConfirmModal
- **修复方案**：
  1. 删除 `CronDeleteDialog.vue` 文件（37 行）
  2. CronView.vue 删除 CronDeleteDialog 的 import、模板引用、`deleteModalOpen`/`deleteTarget` ref 和 `closeDeleteDialog`/`confirmDelete` 函数
  3. 新增 `import { useConfirm }`，重写 `deleteJob` 为 async 调用 `confirm()` Promise
- **验证**：vue-tsc 通过

### QA-008（Warning）— z-index 全局层级体系重建

- **文件**：13 个组件（AgentsView、CronView、SkillsView、BaotaCredentialsDialog、ProjectWorkspacePicker/Edit/CreateDialog、DiagnosticsBundleDialog、ToastHost、DesktopUpdateIndicator、ConfirmModal、PromptCacheKeepaliveDialog）

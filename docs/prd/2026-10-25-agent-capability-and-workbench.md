# PRD：智能体能力自述与工作台协同（2026-10-25）

- 状态：批次 1 实施中（批次 2/3 待开工）
- 触发：用户反馈「智能体不知道工作台内置工具 / 不知道有没有真读自己的定义 / 桌宠移不出窗体 / 右键是浏览器的 / 会话排版错乱 / 团队没有成员卡片 / 协同分工不可靠 / 推理档位与记忆对它们没用」
- 档位：**L**（跨 core / gui / webui 三层，含新 RPC 与交互变更）

## 1. 问题（用可观察现象描述）

| # | 现象 | 证据来源 |
|---|---|---|
| P1 | 主智能体被问「你能操控内置浏览器/终端/编辑器吗」时答"不能"或含糊；实际这些能力存在 | 用户原话；`sandbox.terminal.shells` 探针 200 |
| P2 | 无法回答「这次到底有没有加载我的智能体定义」 | 无任何 RPC 暴露 persona 来源/字节/哈希 |
| P3 | 桌面桌宠只能拖顶栏一小条，拖不出 360×420 窗体 | `PetOverlayView.vue` 仅 drag-handle 绑定 pointerdown |
| P4 | 桌面端右键弹出 Chromium 默认菜单（重新加载/检查/另存为） | WebView2 默认行为，全仓无 `contextmenu` 全局拦截 |
| P5 | 任务结束后历史会话排版错乱、内容居中 | `AssistantMessage.vue` `.msg-ai{width:var(--chat-col);margin:0 auto}` + 结束态卡片 |
| P6 | 团队运行只有汇总卡，无逐成员动向卡片 | `OrchestrationRunCard.vue` 无 member 级视图 |
| P7 | 编排开关多选/少选/全开时分工不稳定 | 无"开关组合 → 分工"的契约测试 |
| P8 | 推理档位/记忆只对主代理生效，子代理与团队成员不受影响 | `subagent.rs` 全仓 0 处 `ThinkingEffort` |

## 2. 目标

- G1：主智能体**知道自己有什么**（工具/MCP/skills/内置面），并能被外部验证（`agent.selfcheck`）。
- G2：用户能一键看到「定义是否真被加载」：persona 来源、字节、哈希、关键标记。
- G3：桌宠整卡可拖、可拖出窗体（窗口随拖动移动），双击抚摸/右键菜单不退化。
- G4：桌面端右键是**本应用菜单**，不再出现浏览器菜单。
- G5：历史会话排版在"进行中/已结束"两态一致，不再出现居中错位。
- G6：团队运行有**逐成员卡片**（角色、当前动作、耗时、产出摘要）。
- G7：编排开关任意组合（全关/部分/全开）都不改变"能完成任务"这一底线；产出质量有质量门。
- G8：推理档位与记忆对主代理/子代理/团队成员**同一口径生效**。

## 3. 非目标（本 PRD 明确不做）

- NG1：不重写编排引擎（`orchestration/*`）的 DAG 调度算法；只在装配点补"继承与兜底"。
- NG2：不做 MCP 服务器市场/自动安装。
- NG3：不做桌宠皮肤商店、不引入新的 3D 资产。
- NG4：不改 `verify.sh --all` 的层数与 README 计数口径（改动需独立批次）。
- NG5：不在本批处理 `webui/src/views/ChatView.vue` 的结构性重构（并发写入者正在改该文件）。

## 4. 用户故事与验收（EARS）

| ID | 故事 | 验收（可观察） |
|---|---|---|
| U1 | 作为用户，我问智能体"你能做什么"时，它列出真实工具而不是猜 | `agent.selfcheck` 返回 `tools.names` 与 `tools.count`；主代理提示词含"先查 selfcheck"条款 |
| U2 | 作为用户，我要确认我的智能体定义被加载 | selfcheck 返回 `persona.bytes>3000`、`sha256`、`markerOk=true` |
| U3 | 作为用户，我把桌宠拖到任意位置（含拖出原窗体范围） | 整卡 pointerdown 可拖；窗口 x/y 随之变化；松手落位；双击仍抚摸 |
| U4 | 作为用户，我在桌面端右键，看到的是应用菜单 | 右键出现「复制/粘贴/全选/检查元素(dev)」等应用菜单，无 Chromium 菜单 |
| U5 | 作为用户，任务结束后历史消息排版与进行中一致 | 同一 `data-message-id` 的 bounding box 在 done 前后 `left/width` 不变 |
| U6 | 作为用户，我能看到团队每个成员在做什么 | 团队卡片内每个成员一行/一卡：角色、状态、耗时、产出摘要 |
| U7 | 作为用户，我随便勾选编排开关，任务都能完成 | 参数化测试：8 种开关组合下 `dispatch` 均产出非空分工且至少有 1 个执行者 |
| U8 | 作为用户，我把档位调到 deep，子代理也 deep | 子代理请求体 `reasoning_effort` 与主代理一致（单测断言） |

## 7. 风险

- R1：全局拦截 `contextmenu` 可能影响输入框粘贴/开发者检查 → 输入框/文本域放行原生菜单，dev 模式保留"检查元素"入口。
- R2：桌宠整卡拖动可能与"抚摸点击"冲突 → 用 4px 位移阈值区分 click 与 drag。
- R3：selfcheck 构建 ToolRegistry 有 I/O 成本 → 结果缓存 30s，且只读。
- R4：并发写入者仍在改 `ChatView.vue`/`useChatSend.ts` → B2 前先看 mtime，避免抢改。

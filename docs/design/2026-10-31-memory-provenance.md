# 记忆溯源抽屉（Memory Provenance Drawer）

> 状态：**已实现（前端 + 后端结构化投影）** · 2026-10-31
> 代码：`core/src/assistant/projection.rs` · `core/src/assistant/brief.rs`
> 前端：`webui/src/composables/shell/useProvenance.ts` · `webui/src/components/shell/ProvenanceDrawer.vue`
> 挂载：`shell.overlay` 插槽（`registerProvenance.ts`，由 `main.ts` 安装）
> 设计谱系：与本仓 `2026-10-31-attention-first-workbench.md` 同一套「守正创新」方法，不引入第二套动效 tokens。

---

## 1. 为什么要做（5 Why）

1. **为什么用户不信任「它记得我」？** 因为记忆只在回答里偶发显形，用户无法在事前检查。
2. **为什么事前看不到？** 简报是后端合成后直接进提示词的，前端从未渲染过它的结构。
3. **为什么前端没渲染？** 因为出参只有 `budget.notes` 一句中文诊断，机器无法分组、无法本地化。
4. **为什么只给一句中文？** 因为投影（L1/L2 去污染）最初被当作内部实现细节，而不是**可审计的决策**。
5. **根因**：记忆系统的「读」与「写」都有测试，但「**为什么这条进了 / 那条没进**」没有一等公民的出口。不可审计的记忆 = 不可纠正的偏见。

## 2. 第一性原理（三条，可反驳）

| # | 原理 | 反例即证伪 |
|---|---|---|
| P1 | **投影是决策，不是实现细节。** 每条被丢弃的事实都必须能回答「被谁、按什么规则、为什么」。 | 若某条丢弃只能从日志里猜，P1 就是假的。 |
| P2 | **缺失必须与空集区分。** 网关没给 `projection` ≠ 投影过且一条没丢。 | 若 UI 把「无字段」渲染成「0 条丢弃」，P2 就是假的。 |
| P3 | **记忆只能在用户看得见的地方被纠正。** 展示不可操作的信息不算透明。 | 若抽屉只读却不能定位到来源，它只是另一块装饰。 |

## 3. 系统三层

### L1 布局 —— 右侧抽屉，不抢注意力

- 位置：右侧 360px，`top/bottom/right: 0`，`z-index: 60`。左下角已被注意力货架占用（`z-index: 55`），右侧让开桌宠与悬浮球。
- 排版：**发丝分隔线 + 行式条目**，不堆卡片。事实两行（正文 / `source · score`），丢弃项带 reason 标签。
- `<900px` 整块不渲染：窄屏没有「余光」这回事，抽屉会直接变成遮挡。

### L2 交互 —— 检查，不裁决

- `Alt + P` 全局切换；`Esc` 关闭；打开时聚焦标题，关闭后把焦点还回触发前的元素。
- 顶部刷新、底部复制摘要。剪贴板不可用时**静默降级为可读提示**，不抛未捕获异常。
- 非模态（`aria-modal="false"`）：不加遮罩，用户仍可与主界面交互。

### L3 动效 —— 只编码「抽屉状态」

- 只用 `transform` + `opacity`；时长/缓动全部走 `--dur-*` / `--ease-*` token。
- `prefers-reduced-motion` 降级为**纯淡入**（取消位移，不取消反馈）。
- 没有打开/关闭跃迁就不播动画。

## 4. 后端契约（本设计的承重墙）

`assistant.brief.get` 的出参新增：

```json
"projection": {
  "policy": "l1_unpredictable_only",
  "droppedCount": 2,
  "dropped": [
    { "key": "project:marguerite#src/lib.rs::…", "reason": "foreign_project" },
    { "key": "cross_project::…", "reason": "low_score" }
  ]
}
```

- **仅当真的做过投影**（`projection_policy.is_some()`）才出现；否则整字段缺席。
- `dropped` 顺序 = 投影决策顺序（确定性）；`droppedCount` 与数组长度一致。
- `budget.notes` 的中文诊断**保持原样**，两条出口不互相替代（机器读结构，人读备注）。

## 5. 决策台账

| ID | 决策 | 备选 | 理由 |
|---|---|---|---|
| D1 | 抽屉放**右侧** | 左侧 / 底部 / 中央浮层 | 左侧被导航与货架占，底部被输入框占，中央抢焦点；右侧是唯一可长期停留的「检查区」。 |
| D2 | **不**做就地「删除事实」 | 抽屉里一键删记忆 | 后端目前没有删除自动事实的 RPC（计划 §8 已记为缺口）。伪造一个点了没反应的删除按钮，正是本仓禁止的「假完成」。 |
| D3 | 缺失 `projection` 显示**诚实空态** | 当作 0 条丢弃 | 两者语义不同；混同会让用户以为投影「什么都没丢」，而真实原因是网关没提供。 |
| D4 | 注册进 `shell.overlay` | 写进 `ChatView.vue` / `App.vue` | 插槽是 append-only 扩展缝；`App.vue` 已 96 KB，只加一行 `<SlotHost>`。不改聊天视图意味着零回归面。 |
| D5 | 不新增 RPC、不新增依赖 | 新增 `assistant.projection.list` | 新增方法要在 Rust/Python 两侧各实现一次，是本仓最高频的双实现漂移形态。 |

## 6. 经济性三视角

- **成本（C）**：零新增 RPC、零新增模型调用、零新增依赖；新增 2 个前端模块 + 1 个注册器 + 13 条前端测试 + 4 条后端测试。
- **缓存（E）**：抽屉只在用户打开时读一次 `assistant.brief.get`，不进入系统提示与工具目录，**不影响 provider 前缀缓存**。
- **体感（T）**：把「它为什么记得」从不可见变为可检查；它不提高召回率，但让召回错误**可被定位**，这是可纠正性的前提。

## 7. 诚实边界

1. **未真机验证**：验证止于 `vue-tsc`、单测、13 道前端守卫；未在打包后的 Tauri 窗口里检查与桌宠/悬浮球的遮挡关系。
2. **不能删事实**：抽屉只读；删除自动事实仍缺 RPC（见 D2）。
3. **不覆盖全部记忆路**：只展示 `assistant.brief` 这一路的钉住/偏好/事实/投影；会话内 tiered / 短期 FTS 的命中明细仍无 RPC 出口。
4. **`Alt + P` 未进设置页快捷键表**：目前只在组件内监听，未纳入可发现性。

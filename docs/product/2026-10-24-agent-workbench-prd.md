# 玛格丽特 · Agent 工作台与任务质量 PRD

> 版本：v1.0（2026-10-24）
> 状态：待评审
> 依据：用户两轮反馈（工作台交互、远程、终端、编辑器、预算与门禁）+ 竞品研究（见 `docs/research/2026-10-24-agent-workbench-competitive-research.md`）+ 现有代码勘察
> 说明：文中 `[Assumption, TBD]` 是尚未由用户确认的产品假设；`[TBD]` 是必须由产品决策补齐的空白。

---

## 1. 背景与目标

### 1.1 观察到的问题（来自真实使用，不是推测）

1. 桌面端「工作位置」里的云端/远程不可选；SSH 协同设置却引导用户安装 Radmin VPN。
2. 未绑定项目时，工作区与工作位置控件存在感不足，用户不确定「任务会跑在哪」。
3. 工作台右缘「+」菜单被裁切、只能看到半个框体，部分区域点不到；打开再关闭后入口消失。
4. 沙箱终端「不像终端」：输出会丢、无颜色、无历史、工作目录不是项目。
5. 项目树与代码编辑器没有打通：点文件没反应、编辑器会莫名弹出、没有右键菜单。
6. 任务完成后缺少可复核的交付证据；预算/轮次/门禁的硬编码让人感觉「被限制」而不是「被保护」。
7. 任务成果质量不稳定：有时只是「说做完了」，没有可执行的验证。

### 1.2 产品判断

- 用户要的不是「更多按钮」，而是**一个可以长期信任的执行环境**：位置明确、工具可用、结果可验收。
- 「限制」应表现为**可见、可调、可解释的预算**，而不是散落在代码里的常量。
- 「远程」的产品形态是**远端执行端**，SSH 只是连接方式；不应要求第三方组网工具。

### 1.3 目标（可观察，不编造指标）

- 用户能在同一屏内同时看到对话、项目树、编辑器/终端，且任一入口不因状态变化而消失。
- 用户能从项目树连续完成「展开 → 双击打开 → 编辑 → 保存 → 重命名/删除 → 在文件管理器定位」。
- 用户能在终端里连续执行多条命令并回看完整输出，工作目录默认是当前项目。
- 未绑定项目时，用户仍能清楚看到「工作位置（本地/远程）」并可切换。
- 任务结束时，用户能看到：改了什么、验证了什么、**没验证什么**、花了多少预算。
- 任何触顶/中止都有明确原因，且可调整预算后继续。

## 2. 范围

### 2.1 P0（最小完整旅程）

1. 工作台与右侧栏共存，入口常驻。
2. 项目树 ↔ 编辑器打通（含右键菜单与文件操作）。
3. 终端可用（真实 PTY 或等价能力、完整输出、项目 cwd、历史与清屏）。
4. 工作位置常驻（本地/远程），远程可真实连接远端执行端，不引导 VPN。
5. 预算自适应（轮次/超时/重试/花费/上下文），模型可声明，触顶可解释。
6. 完成验收与交付回执（证据优先，未验证显式标注）。

### 2.2 P1（增强，不阻塞 P0）

- 编辑器语法高亮与 diff 查看；多标签脏状态与外部修改提示。
- 终端后端选择（Native / WSL / Docker）与尺寸自适应。
- worktree 隔离、同一任务多方案对比（best-of-n）。
- 压缩边界与摘要可视化；成本看板按任务聚合。

### 2.3 明确不做（本轮）

- 自建云厂商运行时（云端仍是 `[TBD]`）。
- 让用户安装任何第三方组网/VPN 工具。
- 用 LLM 裁判替代可执行证据。

## 3. 产品模型

### 3.1 角色

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 用户 | 发起任务、审批、验收 | 选择工作区/工作位置、调整预算、审批危险操作、终止任务 |
| 主智能体 | 规划与执行 | 在预算内调用工具、声明预算档位、请求审批 |
| 子代理/团队 | 分工执行 | 继承预算、上报证据、不可越过硬护栏 |
| 验收官（可选） | 独立判定完成 | 只读证据、输出裁决，不执行修改 |

### 3.2 核心对象

| 对象 | 定义 | 生命周期 |
|---|---|---|
| 任务（Task） | 一次用户请求及其执行过程 | 创建 → 执行 → 待验收 → 完成 / 中止 / 触顶 |
| 工作区（Workspace） | 任务读写的本地或远端目录 | 未绑定 → 已绑定 → 断开 |
| 工作位置（Work Location） | 执行端位置：本地 / 远程网关 / 云端 | 选择 → 连接 → 使用 → 断开 |
| 预算（Budget） | 轮次、单步/整轮超时、重试、花费、上下文 | 自动分档或模型声明 → 钳制 → 消耗 → 触顶 |
| 交付回执（Receipt） | 变更清单 + 验证证据 + 未验证项 + 预算消耗 | 生成 → 可复核 → 可导出 |

### 3.3 完成定义

任务完成必须同时满足：

1. 有用户可读的结果说明；
2. 有产物或变更清单（可为空，但需显式说明「无文件变更」）；
3. 有验证证据，或显式标记「未验证」及原因；
4. 没有未解释的触顶/中止；
5. 用户可一键复核（打开产物、查看 diff、重跑验证）。

## 4. 功能需求

### FR-01 工作台与右侧栏共存

**目的**：让对话与工具同屏可用，不互相遮挡。

**布局**：右侧栏与工作台共享一条「右侧占用宽度」；工作台展开时，右侧栏与其折叠按钮整体左移该宽度。

**规则**

1. 工作台展开且屏幕宽度足够时，两者并排；屏幕不足时工作台以降级形态（抽屉/覆盖）出现，并保证可关闭。
2. 工作台入口的可见性只由「能力可用且当前路由支持」决定：
   - 有标签时：标题栏入口可见；
   - 无标签或工作台收起时：右缘常驻入口可见。
3. 任何弹出菜单必须渲染在视口内且不被祖先容器裁切；点击菜单外部或按 Esc 关闭。
4. 关闭菜单/面板后，入口保持可见。

**状态**

| 状态 | 标题栏入口 | 右缘入口 | 面板 |
|---|---|---|---|
| 无标签 | 隐藏 | 显示 | 隐藏 |
| 有标签·展开 | 显示 | 隐藏 | 显示 |
| 有标签·收起 | 隐藏 | 显示 | 隐藏 |

**异常**：屏幕宽度变化导致布局模式切换时，面板内容不丢失。

### FR-02 项目资源管理器（文件树）

**目的**：在对话侧栏内完成常见的文件操作，不必切换页面。

**触发**：右侧栏「树」标签；或对话输入框「+ → 工作区文件」。

**布局**：工具栏（刷新/新建文件/新建文件夹/全部折叠 + 根名称）+ 树列表 + 底部操作提示。

**规则**

1. 目录原地展开，懒加载子项；折叠保留已加载缓存，刷新时保留展开状态。
2. 单击文件=选中；双击文件=在代码编辑器打开；单击/双击目录=展开或收起。
3. 右键菜单项：
   - 文件：在代码编辑器中打开、重命名、删除、复制路径、在文件管理器中显示；
   - 目录：新建文件、新建文件夹、重命名、删除、复制路径、在文件管理器中显示。
4. 新建/重命名使用名称对话框：名称不得为空，不得包含 `/`、`\`、`..`。
5. 删除前必须确认；目录删除默认拒绝非空目录，确认框中明确「递归删除」。
6. 所有写操作必须落在当前工作区内；越界请求被拒绝并提示原因。
7. 操作成功后局部刷新父目录并保留展开状态；失败保留原状态并展示后端错误。

**空态/异常**：未绑定工作区时展示解析中的工作区根；工作区不可读时展示原因，不伪造文件列表。

### FR-03 代码编辑器

**目的**：让「打开文件 → 修改 → 保存」成为闭环，并让智能体的改动可见。

**触发**：项目树双击文件、右键「打开」、对话输入框「+ → 代码编辑器」。

**规则**

1. 打开文件时显示文件名、绝对路径、语言模式与行号。
2. 编辑后进入未保存状态；保存成功后清除标记并显示保存时间。
3. 支持多标签；同一文件不重复开标签。
4. 文件在磁盘上被外部修改（包括智能体写入）时提示「已变更」，用户可选择重新载入或保留本地编辑。
5. 写入失败（权限/越界/编码）展示后端原因，不假装保存成功。
6. `[Assumption, TBD]` 第一阶段采用 CodeMirror 6 提供语法高亮与基础编辑；diff 视图在 P1 提供。

**状态**：只读 → 可编辑 → 脏 → 保存中 → 已保存 / 保存失败。

### FR-04 沙箱终端

**目的**：让用户像使用本机终端一样执行命令、回看输出。

**触发**：工作台「+ → 沙箱终端」。

**规则**

1. 新终端默认工作目录为当前任务绑定的项目根；未绑定时使用真实工作区根，并在状态栏显示。
2. 输出必须**累积**显示，不允许用增量覆盖整屏。
3. 支持 ANSI 颜色渲染；无法识别或不安全的控制序列不执行、不注入。
4. 支持命令历史（↑/↓）、清屏（按钮或 Ctrl+L）、重启会话、终止会话。
5. 终端区域随容器尺寸变化；若使用 PTY，必须把 cols/rows 同步给后端并对 resize 去抖。
6. 会话状态必须可见：连接中 / 运行中 / 已结束 / 未连接；后端不可用时给出原因与重试。
7. 所有命令仍受 L1/L2/L3 安全护栏与审计约束；危险命令的拦截原因回显到终端。
8. `[Assumption, TBD]` P0 采用真实 PTY；若依赖不可用，降级为行模式并在 UI 明确标注「行模式（无交互）」。

### FR-05 工作位置

**目的**：让用户清楚任务在哪台机器执行，并能真实切换。

**触发**：对话输入框上方的工作位置控件（始终可见）。

**选项**

| 选项 | 行为 | 状态 |
|---|---|---|
| 本地 | 在当前设备执行 | 默认可用 |
| 远程 | 连接另一台运行玛格丽特网关的机器，全部执行在远端 | P0 可用 |
| 云端 | 由托管运行时执行 | `[TBD]`，未接入时禁用并说明 |

**规则**

1. 未绑定项目时控件仍然显示；工作区胶囊显示「选择工作区」。
2. 选择「远程」时打开连接面板：网关地址（`ws://` / `wss://`）、访问令牌（可选）、连接、回到本机。
3. 地址格式非法时阻止提交并说明；连接失败时保留在本机并展示原因。
4. 远程连接成功后，界面明确显示远端主机名；对话、文件、终端均由远端执行。
5. 断开远程时回到本机，并提示当前会话的归属变化。
6. 不出现任何「先安装 VPN / 组网工具」的引导；SSH 仅作为可选连接方式说明。

**状态**：本地 → 连接中 → 远程已连接 → 断开/失败。

### FR-06 预算与停止

**目的**：给足发挥空间，同时让成本与风险可见、可控。

**预算维度**

| 维度 | 自动分档 | 模型可声明 | 硬护栏 |
|---|---|---|---|
| 工具轮次 | 12 / 24 / 40 / 64 | `[[budget:simple\|standard\|complex\|deep]]` | 64 |
| 单步超时 | 120s / 300s / 600s / 900s | 工具参数 `timeout_sec` | 30min |
| 整轮超时 | 15min / 30min / 60min / 120min | 档位 | 2h |
| 请求重试 | 2 / 3 / 4 / 5 | 档位 | 5 |
| 花费 | `[TBD]` | `[TBD]` | `[TBD]` |
| 上下文压缩 | 按窗口余量触发 | 否 | 窗口上限 |

**规则**

1. 档位由任务文本、计划成员数、工具数量推导；模型显式声明优先。
2. 触顶时必须返回可读原因（轮次/时间/重试/花费/取消），并在 UI 提供「提高预算继续」或「收窄任务」。
3. 不允许静默截断；任何被截断的输出/上下文都要在回执中说明。
4. 计划执行、子代理、团队、MCP 工具调用使用同一预算来源，不得各留一套常量。

### FR-07 验收与交付回执

**目的**：让「做完了」变成可复核的事实。

**触发**：任务结束时自动生成；用户也可要求「严格验收」。

**证据优先级**

1. **可执行证据**：测试/构建/运行命令的退出码与关键输出；
2. **结构证据**：文件变更清单、diff、产物路径；
3. **裁判解释**：独立验收官对证据的解释（不替代 1、2）。

**规则**

1. 任务结束展示交付回执：结果摘要、变更清单、验证命令与结果、未验证项、预算消耗。
2. 验证状态只能是：通过 / 失败 / **未验证** / 被阻断；不允许把「没跑」显示成通过。
3. 启用严格验收时，验收官基于证据逐条判定验收标准；不满足则带反馈继续执行，直到通过或触顶。
4. 触顶状态显示为「未完成（触顶）」，并说明还差什么。
5. 用户可从回执直接打开产物、查看 diff、重跑验证。
6. 未产生文件变更时，回执必须显式写「无文件变更」，而不是留空。

### FR-08 任务成果质量

**目的**：让不同类型的任务都有可检查的交付物。

**规则**

1. 交付物按类型生成清单：代码（文件/diff）、文档（文件/预览）、表格（文件/行数）、图片/视频（文件/预览）。
2. 回执中的每个产物都可打开或定位；缺失/被删除的产物标注「已不存在」。
3. 涉及删除、覆盖、发布的动作，必须在回执中单列并标注是否可撤销。
4. `[Assumption, TBD]` 对可验证目标（测试通过、构建成功、CLI 可运行）默认要求至少一条可执行证据。

### FR-09 可观测性

1. 任务级：轮次、工具调用数、token/花费、耗时、模型、压缩次数。
2. 子代理级：每轮思考、工具、耗时（当前已实现 `member_thinking`）。
3. 压缩级：边界事件、压缩前后摘要入口。
4. 失败级：区分治理拒绝、超时、重试耗尽、模型错误、用户取消。

### FR-10 安全与权限

1. 路径必须解析到当前工作区内；拒绝兄弟目录前缀、`..`、软链逃逸。
2. 删除/重命名/覆盖必须二次确认；递归删除需显式声明。
3. 远程连接令牌不写入仓库、不出现在日志。
4. 危险工具仍走审批模式；审批被拒必须回到模型并可见。

## 5. 共享规则

### 5.1 预算档位

- 自动分档是默认，模型声明是覆盖，环境变量是运维兜底，硬护栏是最后一道。
- 任何新增限制必须先回答：它属于「预算」还是「安全护栏」；禁止再引入第三类「散落常量」。

### 5.2 证据等级

| 等级 | 示例 | 可用于判定完成 |
|---|---|---|
| E1 可执行 | `cargo test` 退出 0、构建产物存在 | 是 |
| E2 结构化 | diff、文件清单、日志摘录 | 是（配合 E1 更佳） |
| E3 解释 | 验收官推理、模型自述 | 否（仅解释） |

### 5.3 破坏性操作

删除、覆盖、发布、远程写入：必须确认 + 回执留痕 + 可撤销时提供撤销入口。

## 6. 开放问题

| 编号 | 问题 | 影响 | 当前建议 |
|---|---|---|---|
| Q1 | 「云端」由什么运行时承载？ | FR-05 的云端选项 | 保持禁用并说明，先做远程网关 |
| Q2 | 终端 P0 是否引入 PTY 依赖？ | FR-04 的实现成本与稳定性 | 引入；失败时降级并显式标注 |
| Q3 | 严格验收是否默认开启？ | 成本与延迟 | 默认关闭，用户可为任务开启「严格验收」 |
| Q4 | 远程连接是否要求 TLS/令牌强制？ | 安全 | 公网必须 `wss://` + 令牌；回环可放宽 |
| Q5 | 花费预算的计价口径？ | FR-06 | 先用现有 usage 台账，支持按任务汇总 |

# 通用后端开发规范 v1.1（用户通用标准 · 含 Marguerite 实战案例）

> 版本：v1.1（由 v1.0 项目专属版升格为用户通用标准）
> 生效日期：2026-08-07
> 性质：**本规范是「用户通用后端工程标准」**，不绑定任何单一项目。第 1–9 节为适用于任何语言/框架后端的普适工程纪律；每节末尾的「Marguerite 案例」用本项目的真实代码证明该纪律可落地。第 10 节为可机器校验的自查清单（门禁）。
> 适用范围：任何需要「安全、可测、诚实标注能力成熟度」的后端工程。
> 约束：本规范不规定具体技术选型（框架/数据库/语言），只规定**规则与质量标准**；选型由架构师按项目实际决定。

---

## 0. 如何使用本规范

- **普适原则**（第 1–9 节）= 强制纪律，适用于你手上的任意后端项目。
- **Marguerite 案例** = 同一纪律在一个真实 Rust 引擎上的落地方式，可作模板照抄。
- **第 10 节自查清单** = 交付前的门禁，逐条打勾。

> 经验法则：能用一条可机器校验的规则替代一段「靠人自觉」的约定，就优先用机器校验（成熟度枚举、测试计数、warning 门禁、桩计数）。

---

## 1. 离线优先（Offline-First）

**原则**：系统的核心判定逻辑必须能在**不依赖任何 LLM / 外部 API / 网络**的情况下运行；在线能力（LLM 调用、云存储、远程执行）作为**可插拔层**存在，无 Key / 离线时优雅降级，绝不崩溃或伪造结果。

落地点：
1. **纯规则引擎 vs 在线后端分离**：离线能跑的判定（路由、形态选择、权限初判）放纯函数；在线部分单独成层，缺依赖时自动走降级分支。
2. **依赖注入而非硬编码**：在线后端通过 trait / 配置注入，模块不直接 `new` 具体客户端。
3. **能力注册表标注成熟度**：在线能力在注册表里标 `Partial` 或 `Narrative`，不假装已「全实装」。

**Marguerite 案例**：`Orchestrator::analyze()` 是纯规则引擎（离线永远可用，自动判定编排形态 Solo / MAX / 专家团队 / 集群）；`Orchestrator::dispatch()` 才接真实 LLM 后端，无 Key 时降级。模型层 `core/src/model/llm.rs` 是真实 HTTP 实现，但 `model.cloud` 标 `Real`、离线 `analyze` 不调用它。

---

## 2. 能力注册表 + Maturity 机器校验（杜绝「宣称未落地」）

**原则**：任何对外宣称的「能力 / 特性」必须在**单一注册表**登记，且带一个**机器可校验的成熟度字段**：

| 成熟度 | 含义 | `is_implemented()` |
|--------|------|-------------------|
| `Real` | 已实装且有测试守护 | ✅ |
| `Partial` | 框架/核心实装但含桩或依赖运行环境 | ✅ |
| `Narrative` | 纯叙事，零实现（依赖重型原生或 LLM 后端） | ❌ |

- 禁止仅靠「叙事字段」（如 tier / 分组）宣称已实装——叙事字段会被误读为「已落地」。
- CI 应统计 `Narrative` 占比趋势，让「宣称未落地」无处藏身。
- 能力树（前端展示用）必须来自该注册表，禁止各前端硬编码或各搞一份「超集/子集」。

**Marguerite 案例**：`core/src/domain/capabilities.rs` 用 `CapabilityMaturity` 枚举 + `stats()` 累加 `implemented / narrative`；`by_group()` 供 GUI / TUI / CLI 三前端共读同一份 SSOT。`tool.git` 标 `Real`、`tool.browser` / `sec.os_sandbox` 标 `Partial`、`orch.cluster` 标 `Narrative`。

---

## 3. 治理双闭环（PlanGate + CompletionGate）

**原则**：任何「会改变文件 / 执行命令 / 调网络」的能力，**执行前**与**产出后**必须各过一道门禁：

- **PlanGate（执行前）**：宪法 / 顶层约束 / 资源边界在动作发生前校验，未过即拒。
- **CompletionGate（产出后）**：四检查 + 产出物落盘核验；任何产出物必须经 `evaluate_completion()` 这类终点校验。

新增这类能力**必须**接入双闭环，否则视为未完成。

**Marguerite 案例**：`core/src/governance/` 的 `PlanGate::evaluate`（宪法 C1–C4 前置校验）+ `CompletionGate::evaluate_completion`（四检查 + 自报文件落盘核验）。

---

## 4. 安全分层（fail-closed）

**原则**：凡涉及「执行命令 / 写文件 / 调网络」的路径，必须过**分层安检**，且**默认拒绝（fail-closed）**——判定层返回任何「非明确放行」值都视为拒绝。

至少三层：
- **L1 命令护栏 + 执行沙箱 + SSRF**：命令白名单（fail-closed）、解释器逃逸拦截、路径守卫、超时 kill、内网/元数据地址拦截。
- **L2 静态恶意码扫描**：对生成/执行的代码做启发式扫描（eval/exec 注入、反向 shell、凭证泄露、破坏性操作、不安全反序列化、路径穿越）。
- **L3 权限边界 / 越界裁决**：系统/凭证目录、`.git`、沙箱逃逸意图、跨工作区 `..` 穿越等。

配套子原则：
- **命令白名单**：子命令不在表内一律拒绝（避免 `push --force` / `reset --hard` / `clean -fdx` 被静默放行）。
- **工作区路径守卫**：所有文件操作经 `safe_resolve` 约束在仓库根内，防 `../../etc/passwd` 越界。
- **OS 级隔离（增强项）**：Linux Landlock / macOS Seatbelt 内核级隔离；**不可用平台（如 Windows 无等价物）必须诚实标 `Unsupported`，命令级沙箱为兜底，绝不静默伪造成功**。

**Marguerite 案例**：`core/src/security/`（L1 `command_guard`/`exec`/`ssrf_guard` + L2 `scanner_l2` + L3 `scanner_l3`）+ `core/src/sandbox/`（命令沙箱）+ `core/src/security/os_sandbox.rs`（Landlock/Seatbelt，Windows 诚实 `Unsupported`）。

## 5. API Key / 密钥安全注入模式

**原则**：密钥**只走环境变量 / `.env`（gitignore 忽略）**，**绝不**写进配置文件明文或硬编码到源码。

- 优先级：进程环境变量 > `.env` 文件 > YAML 默认值。
- 进程内用运行时读取（如 `std::env::var`），**不调用已弃用的 `set_var`**，也不依赖第三方 dotenv 库的隐式行为——手动解析 `.env` 更可控、可审计。
- `.env` 必须被 `.gitignore` 忽略；缺失时系统正常运行（离线降级），不报错卡死。

**Marguerite 案例**：`core/src/persistence/config.rs` 的 `apply_env_overrides()`——从项目根 `.env` 与 `$1marguerite/.env` 手动解析 `MARGUERITE_API_KEY` / `MARGUERITE_MODEL` / `MARGUERITE_BASE_URL` / `MARGUERITE_PROVIDER`，非空才覆盖 YAML；有 Key 时 info 日志声明来源，绝不回显明文。

## 6. 测试门禁（零回归 + 零警告）

**原则**：
- 维护一条**测试基线**（如 N 用例 EXIT 0），新增代码**不得破坏**该基线。
- `build` / `test` 不允许**新增 warning**；既有旧 warning 在相关改动时一并清理。
- **桩代码必须显式标注**：未实现的工具/方法用 `code: "NOT_IMPLEMENTED"` 或 `// STUB: <原因>` 标注，**严禁**静默返回空成功（fail-closed 的延伸）。
- CI 应统计 `NOT_IMPLEMENTED` 数量趋势。

**Marguerite 案例**：当前 `cargo test -p marguerite-core` 基线 **lib 893 passed + e2e 5 + perf 1 = 899 用例，EXIT 0，零回归**；零警告门禁；`chain/builtin.rs` 的桩用 `NOT_IMPLEMENTED` 显式标注。

---

## 7. 可测性注入（trait + mock）

**原则**：所有外部副作用（进程执行、网络、文件系统）必须抽象为 **trait 并允许注入 mock**。命名惯例：`XxxRunner` / `XxxTransport`，测试用 `Recording*` 记录型实现。

- 新增带副作用的模块**必须提供可注入 trait**，否则测试门禁打回（无法 mock 就无法守护）。
- 真实实现不走 shell（直接 `Command::new` 二进制），天然免疫 shell 注入。

**Marguerite 案例**：`sandbox::CommandRunner`（`RecordingRunner`）、`deploy::SshTransport`（`RecordingTransport`）、`tools::git::GitRunner`（`SystemGitRunner` + `RecordingGitRunner`）。`tool.git` 经 `GitRunner` trait 注入，测试用 `RecordingGitRunner` 记录调用、不真跑 git。

---

## 8. 分层依赖与逻辑下沉

**原则**：
- **领域层不依赖上层**；编排/API 层依赖领域层 + 能力模块；前端/API 层**只做编排与渲染**，不得重写业务规则。
- **禁止环形依赖**；跨层调用单向向下。
- **内部可变性跨 await**：用 `Arc<Mutex<T>>`，先 `clone` 出锁再跨 `await`，避免 `MutexGuard` 非 `Send` 导致编译失败。
- 能力模块通过编排器暴露的 `set_*` 注入点解耦，便于测试 mock。

**Marguerite 案例**：`domain` 为 SSOT；`orchestration` 依赖 `domain` + 各能力模块；前端只依赖 `orchestration` + `domain`，不直接依赖 `chain`/`sandbox` 内部细节。

---

## 9. 重型桥诚实标注（Real / Partial / Narrative）

**原则**：重型原生能力（浏览器桥、OS 沙箱、集群调度、RPA 等）实装后必须在能力表**诚实标注成熟度**：

- 需要本机特定运行时（如 Chromium）的标 `Partial`，并配 `#[ignore]` 实时集成测试（手动 `cargo test -- --ignored` 运行）。
- 平台不支持内核级隔离等能力的，如实标 `Unsupported`，**绝不静默伪造 Full**。

**Marguerite 案例**：
- `browser_bridge`（`core/src/browser/`）：Chrome DevTools Protocol 重型桥，需本机 Chromium，`tool.browser` 标 `Partial`；实时测试 `#[ignore]`。
- `sec.os_sandbox`（`core/src/security/os_sandbox.rs`）：Linux Landlock / macOS Seatbelt 内核级隔离；Windows 构建**诚实返回 `Unsupported`**（fail-closed 伦理），不伪造成功。

---

## 10. 能力判定与自查清单（门禁速查）

交付前逐条核对：

| # | 门禁项 | 通过标准 |
|---|--------|----------|
| 1 | 离线优先 | 核心判定逻辑不依赖外部 LLM/API/网络即可运行 |
| 2 | 能力注册表 | 所有宣称能力已在 SSOT 登记且带 `maturity` 字段 |
| 3 | 治理双闭环 | 改文件/执行命令/调网络的能力已接入 PlanGate + CompletionGate |
| 4 | 安全分层 | 命令/文件/网络路径过 L1–L3 + 命令沙箱，fail-closed |
| 5 | 密钥注入 | 密钥只走 env/.env，无明文/硬编码；`.env` 已 gitignore |
| 6 | 测试基线 | 新增代码不破坏测试基线；无新增 warning |
| 7 | 桩标注 | 未实现项显式 `NOT_IMPLEMENTED`，无静默空成功 |
| 8 | 可测性 | 带副作用模块提供可注入 trait + mock |
| 9 | 分层依赖 | 无环形依赖；逻辑下沉核心层，前端只渲染 |
| 10 | 重型桥诚实 | 重型原生能力标 Real/Partial/Narrative；不支持平台标 Unsupported |

### 案例：Marguerite 能力对账（实测校准，可作模板）

**已实装且测试守护（✅ Real）**：research / vision / automation / kb（graph/denoiser/integrity + BM25）/ governance / memory（working/episodic/project）/ security（L1+L2+L3）/ recovery / tools（exec/file/rollback）/ deploy（SSH/Baota）/ collab / sandbox / model.cloud（需 Key）/ tool.git / kb.denoiser / kb.integrity。

**部分实装（🟡 Partial）**：orch.expert_team（框架真实，个别内置工具桩）/ tool.mcp_bridge（个别方法未实现）/ tool.browser（需本机 Chromium）/ sec.os_sandbox（Linux/macOS 实装，Windows Unsupported）/ res.self_heal / mem.semantic / model.dual。

**纯叙事（⚪ Narrative，依赖重型原生/LLM 后端）**：orch.cluster / orch.swarm / tool.terminal / tool.fs_watch / tool.uia / auto.uia / kb.ima / vis.audio / model.local / auto_fix_loop / auto_review / 抗幻觉 verifier。

> 历史教训：早期 `capabilities.rs` 仅有 `tier` 叙事字段、无 `maturity` 标志，导致 research/vision/automation/security 等被标 Exclusive 却长期零实现。本规范强制「注册表 + 机器校验成熟度」四步闭环（登记 → 实现 → 接线编排器 → 测试守护），任一步缺即视为未完成。

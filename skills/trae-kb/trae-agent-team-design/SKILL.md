# 自定义智能体与专家团队设计

## 何时用本技能

- 任务跨多个专业领域（设计 + 前端 + 后端 + 测试），单智能体容易顾此失彼。
- 长对话后输出质量下滑，需要按职责隔离上下文。
- 团队产出高度重复，需要重新划分职责边界。

不适用：单文件小改动、纯问答、一次性查询。

## 核心原则

1. **按职责切，不按技术栈切**：切分依据是「谁对什么结论负责」，不是「用了什么库」。
2. **一个成员一份结论**：每个成员只交自己职责内的判断，末尾写「未决问题」与建议接手人。
3. **隔离上下文**：成员只拿完成自己那份工作所需的最小材料，避免整段长对话复制。
4. **必须有验收角色**：至少一个成员负责挑错（测试/合规/性能），否则团队会集体乐观。
5. **成员数 2-4 最稳**：超过 5 个后协调成本与重复度陡增。

## 8 类专家职责边界（可直接作为团队名册）

| 角色 | 负责什么 | 明确不做什么 | 典型产物 |
| --- | --- | --- | --- |
| UI 设计师 | 组件与状态设计、视觉层级、设计 token、跨屏适配 | 不写业务逻辑 | 组件清单、状态矩阵、token 表 |
| 前端架构师 | 组件架构、状态管理、性能与构建、可访问性 | 不定后端数据模型 | 目录结构、数据流方案、性能清单 |
| 后端架构师 | API 契约、服务分层、数据库与缓存、可扩展性 | 不做视觉决策 | 接口契约、表结构、失败路径 |
| API 测试工程师 | 契约测试、边界与错误处理、性能与负载、安全用例 | 不改业务实现 | 用例表、复现命令、缺陷分级 |
| AI 集成工程师 | 模型接入、提示与工具编排、推荐/自动化、模型部署 | 不替代产品决策 | 集成方案、调用链、成本估算 |
| DevOps 工程师 | CI/CD、基础设施即代码、监控告警、发布策略 | 不写业务功能 | 流水线定义、回滚方案、SLO |
| 性能优化师 | 基准测试、瓶颈定位、端到端优化、优化验证 | 不做无度量的「优化」 | 基准数据、热点清单、前后对比 |
| 合规审查员 | 条款与隐私审查、法规映射、风险分级 | 不提供正式法律意见 | 风险清单（可做/需整改/不可做） |

## 团队组合模板

### 全栈交付（默认）

```text
前端架构师 → 后端架构师 → API 测试工程师 → DevOps 工程师
依赖：测试依赖前两者产出；DevOps 依赖测试通过
```

### 设计到代码

```text
UI 设计师 → 前端架构师 → 性能优化师
依赖：前端依赖设计 token；性能优化在功能完成后介入
```

### AI 功能落地

```text
AI 集成工程师 → 后端架构师 → 合规审查员
依赖：合规审查在所有方案确定后、上线前
```

### 故障排查

```text
后端架构师（定位） → 性能优化师（量化） → API 测试工程师（回归）
```

## 组建步骤

1. **写清目标与验收**：一句话目标 + 3 条可验证的验收标准。
2. **列职责缺口**：目标需要哪些结论？每个结论由谁负责？缺口即成员。
3. **写成员简报**：每个成员一段 `brief`，含「只交什么」「必须带什么证据」。
4. **定依赖**：谁必须先完成；无依赖的成员并行执行。
5. **定聚合规则**：冲突时以证据强度为准；无法裁决则升级给用户，不自行折中。
6. **验收**：逐条对照验收标准，未通过则回到对应成员，而不是让所有人重跑。

## 成员简报模板

```text
【团队分工：<角色>】
目标：<整体目标>
你的职责：<一句话>
交付物：<结构/字段>
证据要求：文件路径 + 行号 / 命令输出 / 数值
禁止：替其他成员下结论；编造未执行的验证
末尾：未决问题 + 建议接手人
```

## 常见失败与修法

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 成员结论几乎一样 | brief 只写了角色名 | 补「只交什么」与证据要求 |
| 团队比单智能体还慢 | 成员太多 + 串行依赖过深 | 压到 2-4 人，去掉无产出的中间层 |
| 结论互相矛盾没人裁决 | 缺聚合规则 | 预置「证据强度优先」与升级条件 |
| 长任务中途跑偏 | 没有里程碑 | 每成员结束即验收，不攒到最后 |
| 成本高但质量没提升 | 给小任务上了大团队 | 用「是否需要多份独立结论」作判据 |

## 自检清单

- [ ] 每个成员都有明确的「不做清单」
- [ ] 每个成员都有证据要求
- [ ] 至少一个验收/挑错角色
- [ ] 成员数 ≤ 4（除非有明确理由）
- [ ] 依赖关系无环，可并行的已并行
- [ ] 有冲突聚合规则与升级条件

# 会议纪要工程化

## 流水线

```text
音频输入
  → 采样与归一化（16kHz 单声道）
  → VAD（切掉静音，分段）
  → 说话人分离（按段聚类）
  → ASR 转写（Whisper 类模型）
  → 文本规整（标点、数字、专名）
  → 结构化摘要（议题 / 结论 / 待办 / 负责人 / 截止）
  → 关键词与检索索引
```

**顺序不可颠倒**：先 VAD 再 ASR 能显著减少无效计算；先分离再转写能让每段带说话人标签。

## 各环节要点

### VAD（语音活动检测）

- 目的：去掉静音与噪声段，降低 ASR 成本；同时给出天然的分段边界。
- 参数：最短语音段 250-500ms，最短静音段 300-500ms，前后留 100-200ms 余量（避免吞字）。
- 常见错误：静音阈値过高导致吞掉轻声开头；过低导致噪声被当语音。

### 说话人分离

- 先对每个语音段提取声纹嵌入，再聚类（阈值可调，会议场景通常 2-8 人）。
- 短段（<1s）聚类极不稳定：优先用相邻同段合并，或标记为「未知说话人」而不是硬分。
- 说话人编号与真实姓名的映射需要人工确认一次，不要自动猜。

### ASR 转写

- 模型分档：小模型快、适合实时；大模型准、适合离线批处理。
- 批量优于逐段：一次传入较长音频能利用上下文，减少断句错误。
- 专名与缩写在通用模型上常错：维护一份项目词表做后处理替换。
- 输出保留时间戳与置信度，便于定位低质量片段。

### 结构化摘要

固定输出结构，避免「一段流畅但没信息」的总结：

```markdown
## 议题
## 结论（含决策依据）
## 待办
| 事项 | 负责人 | 截止 | 来源时间戳 |
## 风险与分歧
## 未决问题
```

规则：
- 结论必须有原文支撑，无支撑的一律放进「未决问题」。
- 待办必须能落到人；找不到负责人的写「待指派」。
- 不生成原文没有的判断（尤其是数字与时间）。

## 性能与内存

| 瓶颈 | 表现 | 处理 |
| --- | --- | --- |
| 长音频一次性载入 | 内存峰值高、可能 OOM | 流式分块，块间保留 1-2s 重叠 |
| 模型常驻内存 | 冷启动慢、占用高 | 单例加载 + 空闲释放 + 预热一次 |
| 逐段调用 ASR | 耗时线性放大 | 批量合并短段 |
| 重复转写 | 同一音频多次处理 | 按内容哈希缓存结果 |
| 全量重算摘要 | 长会议越跑越慢 | 分段摘要 + 最终归并 |

## 质量验收

- 转写：随机抽 10 段，人工核对字错率与断句。
- 分离：随机抽 10 段，核对说话人是否混淆。
- 摘要：待办条目逐条回原文定位，确认无编造。
- 性能：记录音频时长 / 处理时长比值，给出可复现基准。
- 隐私：明确音频与转写文本的存储位置、保留时长与删除方式。

## 常见失败

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 会议开始几分钟没内容 | VAD 阈值过严 | 降低阈值，保留起始余量 |
| 说话人频繁跳变 | 聚类对短段不稳 | 合并相邻段，短段标未知 |
| 待办张冠李戴 | 摘要越权推断 | 只提取原文明确指派 |
| 长会议超时 | 全量一次处理 | 分块 + 增量摘要 |
| 转写慢到不可用 | 大模型 + 逐段调用 | 小模型批处理，大模型只修正低置信段 |

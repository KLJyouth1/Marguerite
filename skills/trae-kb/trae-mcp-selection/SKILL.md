# MCP 工具选型与接线

## 先问三个问题

1. **这件事需要外部系统吗？** 不需要（纯推理、纯本地文件）→ 别上 MCP。
2. **有内置工具能做吗？** 有（读写文件、跑命令、网页抓取）→ 优先内置，减少一层故障。
3. **需要长期复用同一套外部能力吗？** 一次性调用 → 直接调 API/CLI 更快。

**MCP 的价值是「把外部系统变成模型能稳定调用的原子工具」，不是「装得越多越强」。** 工具越多，选错工具的概率越高。

## 十类主流 Server 的适用边界

| Server | 解决什么 | 什么时候不该用 | 本地替代 |
| --- | --- | --- | --- |
| **Context7** | 拉取库/框架的**最新**文档与示例，避免用过期 API | 只用标准库、或版本已锁定且熟悉 | 读仓库内 lockfile + 官方文档 |
| **Puppeteer** | 无头浏览器自动化（点击、填表、截图、抓取） | 只需静态 HTML → 用抓取 | 本地 Playwright |
| **Playwright** | 跨浏览器 E2E、可访问性快照、网络拦截 | 只测一个页面的静态渲染 | 单元测试 + 快照 |
| **Sequential Thinking** | 强制把复杂问题拆成有序思考步骤 | 简单任务 → 纯属浪费 token | 直接分步写 |
| **GitHub** | PR/Issue/Actions/代码检索 | 只读一个本地仓库 | git 命令 |
| **Figma AI Bridge** | 读设计稿结构、token、组件，转代码 | 只有截图没有设计文件 | 截图 + 人工核对 |
| **Memory** | 跨会话保存实体与偏好 | 一次性任务 | 项目内文档/规则 |
| **Excel** | 读写 xlsx、公式、多表 | 只是 CSV → 直接读写文本 | Python/脚本 |
| **File System** | 受控目录读写 | 已有内置文件工具 | 内置读写工具 |
| **Chrome DevTools** | 性能面板、网络瀑布、控制台错误、DOM 调试 | 只做功能测试 | Playwright trace |

## 选型决策树

```text
需要外部数据/操作？
├─ 否 → 用内置工具或纯推理
└─ 是
   ├─ 是浏览器交互？ → Playwright（E2E）/ Puppeteer（抓取）
   ├─ 是第三方 API 文档？ → Context7
   ├─ 是代码托管协作？ → GitHub
   ├─ 是设计稿？ → Figma AI Bridge
   ├─ 是表格文件？ → Excel
   ├─ 是性能问题？ → Chrome DevTools
   └─ 是跨会话记忆？ → Memory
```

## 接线检查清单（接完必须实测）

1. **进程起得来**：启动无报错，`initialize` 成功。
2. **工具列得出**：`tools/list` 返回非空，名字与文档一致。
3. **真调一次**：用一个最小输入调用，确认返回结构符合预期。
4. **失败可见**：断开服务时调用必须报错，而不是静默返回空。
5. **超时可控**：设置合理超时，避免长挂。
6. **权限最小**：只给必要目录/仓库/令牌。
7. **密钥不入库**：配置走环境变量或本地配置，不写进仓库。

## 常见故障

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 模型说「没有工具」 | Server 未启动或工具未注册 | 查进程与 `tools/list` |
| 工具调用参数报错 | 参数名与 schema 不一致（如 `args` vs `arguments`） | 对照 schema 传参 |
| 调用一直挂住 | 未设超时 / 子进程等待输入 | 设超时，禁用交互式提示 |
| 结果为空但无报错 | 服务端错误被吞 | 要求显式错误码，验证失败路径 |
| 装了但从不被选中 | 描述太泛 | 在工具描述里写清「何时用」 |

## 诚实边界

- MCP 只是通道：**服务本身不可用，MCP 也救不了**。
- 工具描述写得好不好，直接决定模型会不会选它。
- 不要用 MCP 包装「本来一行命令就能做完」的事。

## 自检清单

- [ ] 已确认内置工具不能替代
- [ ] 已确认是为外部系统而接
- [ ] 启动、列表、真实调用三步都验过
- [ ] 失败路径会显式报错
- [ ] 超时与权限已收紧
- [ ] 密钥未入库

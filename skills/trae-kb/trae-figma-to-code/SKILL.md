# 设计稿到代码

## 链路总览

```text
需求梳理 → 结构提取（设计稿） → 原型生成 → 转码实现 → 视觉回归
   ①            ②                  ③            ④            ⑤
```

任一环节跳过，最终都会以「还原度不够」的形式返工。

## ① 需求梳理

产出：一页说明，含

- 页面目标与主行动点（用户来这里干什么）
- 区块清单与优先级
- 状态清单：默认 / 加载 / 空 / 错误 / 无权限 / 超长文本
- 非目标（这次不做）
- 响应式断点要求

## ② 结构提取（关键环节）

从设计稿提取的不是像素，而是**结构 + token**：

1. **布局骨架**：几栏、是否栅格、哪些区域可伸缩。
2. **组件清单**：按钮/输入/卡片/表格等，各自有哪些变体与状态。
3. **设计 token**：颜色、字号、行高、间距、圆角、阴影 —— 全部映射成变量。
4. **素材**：图标、插画、图片，记录来源与导出尺寸。
5. **交互标注**：悬停、点击、展开、滚动行为。

若只有截图没有设计文件：先人工确认上述五项，再动代码。**不要从截图里「猜」字号和间距。**

## ③ 原型生成

- 先做**静态高保真**（不接数据），确认版式与层级。
- 再补**状态**（加载/空/错误），这一步最容易被跳过，也最容易被用户发现。
- 最后接**假数据**走通交互。
- 原型阶段不引入业务逻辑，避免返工时牵一发动全身。

## ④ 转码实现

1. 先落 **token 层**（CSS 变量 / 主题），再写组件。
2. 组件按「原子 → 组合 → 页面」顺序实现，每个组件自带全部状态。
3. 布局用 Flex/Grid，不用绝对定位堆。
4. 文案、图标、间距全部来自 token 或设计标注，不手写魔法数字。
5. 每个组件实现完立即在浏览器里对比一次设计稿。

## ⑤ 视觉回归

- 同尺寸截图对比：布局、间距、字号、颜色、圆角逐项核对。
- 不同断点各截一次（窄屏必须看）。
- 检查状态：加载/空/错误/长文本。
- 检查交互：悬停、聚焦、禁用、键盘 Tab 顺序。
- 记录差异清单并逐条修，不凭「感觉差不多了」。

## 还原度差异的常见根因

| 差异 | 根因 | 修法 |
| --- | --- | --- |
| 间距总是差几像素 | 没有统一间距体系 | 建立 8pt 体系，禁止手写零散值 |
| 字号看起来偏小/偏大 | 设计稿是 2x 切图 | 统一按逻辑像素换算 |
| 颜色偏灰 | 色值被透明度叠加 | 用设计 token 原值，别二次调 |
| 阴影脏 | 多层阴影叠加 | 只用一层柔和阴影 + 描边 |
| 窄屏错位 | 只按桌面宽度写死 | 用流式布局 + 断点 |
| 图标模糊 | 位图当矢量用 | 用 SVG，按 1x/2x 校验 |

## 与团队协作

- UI 设计师：交付组件变体与状态矩阵，不只给一张主视觉。
- 前端架构师：把 token 与组件边界定死，避免实现时各自发挥。
- 性能优化师：在功能完成后检查图片体积、字体加载、首屏渲染。

## 自检清单

- [ ] 需求含状态清单与非目标
- [ ] 结构提取含布局/组件/token/素材/交互五项
- [ ] 原型含加载、空、错误状态
- [ ] 代码中无手写魔法数字
- [ ] 各断点截图核对过
- [ ] 差异清单已逐条关闭
